# Раздача скоупа — наша вилка и как её прогнать

Грамота зоны — в `share/README.md` (её пишет architect): что такое раздача, чего ей нельзя и
почему она отдельная. **Здесь — то, что сделал owner-share:** наше изделие под форму стыковки
и чем оно проверяется.

---

## 1. Розетка — в каноне, а не здесь

**Форма стыковки целиком — `WORLD2` 3.4, раздел «Розетка раздачи — вся форма стыковки».** Там
адрес, две ручки, пароль, что раздача не делает, чего не вправе тот, кто с ней разговаривает,
что говорят статусы и что из этого следует для версий. Больше в форме ничего нет.

**Здесь её нет намеренно.** Пока форма лежала в этом файле, чужая раздача обязана была читать
документ нашей зоны — то есть быть догоняющей, а не равной, ровно против `0.3`. Перенесено в
канон 2026-08-18 решением user (`WORLD2-146`).

**Что это значит для читателя:** всё ниже — **наша вилка, и только она**. Любая другая, которая
держит форму, равноправна нашей — «хоть на ардуино» и хоть написанная юзером с нуля. Сверяться
надо с каноном, а не с этим файлом.

## 2. Наша вилка — что мы выпускаем

**Одна вилка как удобство, а не как единственно возможная** (`0.3`). Всё в этом разделе
заменяемо на что угодно, что держит форму из `3.4`.

| | |
|---|---|
| образ | `ghcr.io/omnifield/world-share` — один статический бинарь, **больше в образе нет ничего** |
| рецепт | `share/compose.yaml` — им раздачу поднимают на названной машине |
| порт | `8070` (дверь — 8080, контроллер — 8090; одна машина законно держит все три) |
| состояние | `/state/scope.json` в томе `<имя>-state` |
| пароль | `SHARE_PASSWORD` при подъёме; **без него раздача не поднимается вовсе** |

Ни шелла, ни пакетного менеджера, ни `curl` в образе нет: раздача держит личность юзера, и всё,
что лежит рядом с ней, лежит рядом с его ключами. Стук в живость — команда самого бинаря
(`share knock`), а не отдельный инструмент и **не третья ручка**.

### Значения

| | |
|---|---|
| `SHARE_PASSWORD` | обязательно, без умолчания |
| `SHARE_ADDR` | `:8070` |
| `SHARE_STATE` | `/state/scope.json` (в репозитории — `./.state/scope.json`) |
| `SHARE_LIMIT` | предел одной записи, байт; по умолчанию `1048576` |
| `SHARE_KNOCK_TIMEOUT` | сколько секунд ждёт стук |

Предел — не мнение о содержимом, а граница памяти и диска: без него одна оборванная запись
затягивается на весь том. Сам предел форма разрешает держать (`413`), а его величину не задаёт.

### Коды отказов — в теле, и они наши

**Формой стали статусы, тело — изделие изготовителя** (`3.4`, «Что говорят статусы»). Наши
отказы приходят тройкой `{"code":…,"why":…,"ways":[…]}` — код машине, причина и выходы человеку
(`2.3`). **Чужая раздача вправе ответить голым `401` без тела, и это законная раздача**, поэтому
на нашу тройку никто, кроме нас, полагаться не обязан.

| HTTP | code | когда |
|---|---|---|
| 401 | `no-creds` | пароль не назван |
| 401 | `bad-creds` | пароль не подошёл |
| 404 | `no-state` | раздача поднята, состояние ещё не записывали |
| 404 | `no-such-address` | спросили не корень |
| 405 | `bad-handle` | метод не из двух (в ответе `Allow: GET, PUT`) |
| 400 | `empty-state` | пришло ноль байт |
| 400 | `state-not-received` | тело оборвалось на полпути; старое состояние не тронуто |
| 413 | `state-too-big` | больше предела записи |
| 500 | `state-unreadable` · `state-unwritable` | том, права, место |

Два кода на один статус — тоже наше: `401` в форме один, а человеку разница между «не назвал» и
«не подошёл» нужна. Проба стережёт **статус и код**, а не формулировку `why`.

### Подъём на машине юзера — тем же путём, что и любая вещь

Раздача поднимается **рецептом**, а не кодом контроллера (`WORLD2-131`):

```
SHARE_PASSWORD=<пароль> ./deploy/remote.sh add <имя> --addr user@машина --recipe share/compose.yaml
```

Пароль подставляется компоузом при подъёме. Не назван — **компоуз краснеет здесь**, до того как
что-либо уехало на чужую машину (`:?` в рецепте), а не «контейнером, который упал там».

Появление раздачи не потребовало ни строки в соседних зонах — только этот рецепт и образ.

**Версию нашего образа контроллер не подставляет и не сверяет** (`3.4`, «Что из этого следует
для версий», решение user 2026-08-18): что поднимать — говорит рецепт, и только он.

### Путь разработчика зоны

```
SHARE_PASSWORD=… ./share/up.sh          поднять здесь (порт 8070)
SHARE_PASSWORD=… ./share/up.sh --build  собрать образ из исходников и поднять
./share/up.sh status                    контейнер, здоровье, том личности
./share/up.sh down [--with-state]       снять; с ключом — вместе с личностью
go run ./cmd/share help                 то же без докера
```

Поговорить с поднятой раздачей руками:

```
curl -u :<пароль> http://<машина>:8070/                    # взять
curl -u :<пароль> -T состояние.json http://<машина>:8070/  # положить
```

## 3. Чем это проверено

```
./share/probe-share.sh                        зелёный и красный прогон (умолчание)
cd share && go test ./...                     пробы кода
cd share && go run ./cmd/recipecheck compose.yaml   сторож формы записи файла запуска
```

Проба стережёт **свойства**, а не «работает ли»: две ручки и файл целиком · внутрь файла не
смотрим (проходит заведомо не-JSON) · пустые разделы и пустой бренд законны (`WORLD2-135`) ·
пароль проверяет сама раздача · отказ приходит тройкой · **ни одного своего знака в протоколе**
(в ответе нет ни одного нашего заголовка — этим держится «не узнавать свою раздачу», `3.4`) ·
запись затирает предыдущую целиком.

Ломаем нарочно: без пароля не поднимается · без кред · неверный пароль (и запись под ним **не
доезжает до диска**) · третья ручка · раздел в пути · ноль байт · сверх предела.

**Файл запуска стережётся БЕЗ докера и потому всегда** (`WORLD2-140`): сторож `internal/recipe`
читает тот самый `compose.yaml`, которым раздачу поднимают на машине юзера, а проба следом
портит его копию и требует красноты — незакавыченная подстановка с двоеточием (тот самый дефект,
остановивший живой выпуск) и просто незакавыченная подстановка. Рядом стоит обратная проверка:
двоеточие **внутри кавычек** законно, и текст отказа сокращать не надо.

Правило файла запуска одной строкой: **значение с `${…}` — всегда в кавычках.**

**Без докера проба не зеленеет, а говорит вслух:** образ, том и полный разбор компоузом остаются
непрогнанными, и код выхода `3` — НЕПОЛНЫЙ ПРОГОН. «Проверили, что смогли» и «проверили» —
разные слова.

## 4. Чего в нашем изделии нет — и это не забывчивость

Что запрещено **формой** — перечислено в каноне (`3.4`, «Что раздача НЕ делает» и «Чего не
вправе тот, кто с ней разговаривает»); здесь это не пересказывается, а стережётся пробами
раздела 3.

Сверх того мы не добавили и того, чего форма **не** запрещает:

| чего нет | почему |
|---|---|
| разбора и проверки содержимого — хотя вилке это не запрещено | завели бы вторую правду о формате: за содержимым следит контроллер (`2.5` п. 11) |
| условной записи, слияния, версий состояния | цена записи целиком названа в каноне вслух; открывать эту глубь заново незачем (`3.4`) |
| TLS, вторых факторов, своего сторожа | слой юзера, а не наш: базовый слой в мире один — пароль (`3.4`, «Секьюрность — слоями») |
| членства в сети мира (`omnifield-gateway`) | раздача не служба мира: личность старше любой двери |

**Сверка с рынком 2026-08-17**, сделана перед тем, как заводить форму (сама форма с 2026-08-18
живёт в каноне, `3.4`): смотрели HTTP `GET`/`PUT` над одним адресом (RFC 9110, §9.3.4 — `PUT`
заменяет состояние ресурса телом, идемпотентен), `Basic` (RFC 7617) и WebDAV (RFC 4918).
**Взяли первые два, WebDAV не взяли:** он про каталоги, свойства и блокировки (`PROPFIND`,
`LOCK`, `MKCOL`), и чужой вилке пришлось бы повторять весь набор, чтобы считаться раздачей, —
ровно та цена, которую канон запрещает перекладывать на изготовителя вилки. Своего протокола не
изобретаем ни в одной точке.

# Раздача скоупа — форма стыковки, вилка и как её прогнать

Грамота зоны — в `share/README.md` (её пишет architect): что такое раздача, чего ей нельзя и
почему она отдельная. **Здесь — то, что сделал owner-share:** форма, по которой с раздачей
разговаривают, наше изделие под эту форму и чем оно проверяется.

Порядок разделов не случаен. Первый — **розетка**: он один обязателен и один переживёт нашу
вилку. Остальное — про нашу, и заменяемо целиком.

---

## 1. Розетка — что обязано сойтись

Форму задаёт мир, изделие делает изготовитель (`WORLD2` 0.3). Ниже — вся форма. Больше в ней
ничего нет, и это главное её свойство: **чужая раздача равноправна нашей** (`3.4`) — отдал файл
по адресу, принял файл по адресу, проверил пароль. «Хоть на ардуино» — не фигура речи, а
требование к размеру этого раздела.

### Адрес

Адрес скоупа — обычный HTTP-адрес: `http://<машина>:<порт>/`. Состояние отдаётся **в корне и
только в корне**. Разделов, вложенных путей и имён внутри раздачи нет: **две раздачи — два
скоупа**, а не два пути в одной (`3.4`, «Копий нет — есть адреса»).

### Две ручки

| | что делает | ответ |
|---|---|---|
| `GET /` | отдать файл состояния **целиком** | `200` + тело; `404`, если состояния ещё нет |
| `PUT /` | принять файл состояния **целиком** | `204` без тела |

Семантика взята у HTTP, а не придумана: `PUT` просит заменить состояние ресурса тем, что
приехало телом, и он идемпотентен (RFC 9110, §9.3.4). Это ровно «принять файл целиком».

**Третьей ручки нет и не будет.** Ни «здоровье», ни «версия», ни «кто я»: каждая такая ручка —
опознавательный знак, по которому мир начал бы узнавать *свою* раздачу.

### Пароль

`Authorization: Basic` (RFC 7617). Проверяется **сам пароль**; имя в заголовке не смотрится —
личность определяется адресом, а не именем.

```
curl -u :<пароль> http://<машина>:<порт>/                    # взять
curl -u :<пароль> -T состояние.json http://<машина>:<порт>/  # положить
```

**Пароля внутри файла состояния нет и быть не может** — им закрыта сама раздача, а класть его
внутрь значит запирать ключ внутри замка (`3.4`).

### Что раздача НЕ делает

- **не разбирает файл.** Ни JSON, ни версии формата, ни «имя территории не повторяется». За
  содержимым следит тот, кто пишет, — контроллер (`3.4`, `2.5` п. 11);
- **не хранит ничего, кроме файла.** Ни списка юзеров, ни журнала правок, ни второй копии;
- **не знает про мир.** Ни сети `omnifield-gateway`, ни двери, ни контроллера.

### Что обязан и чего не вправе клиент

- **читает СТАТУС**, а тело — как подробность. Наши отказы приходят тройкой
  (`{"code":…,"why":…,"ways":[…]}`), но **чужая раздача вправе ответить голым `401` без тела**, и
  это законная раздача;
- **не узнаёт «свою» раздачу** — ни по заголовку, ни по телу, ни по `realm`. Проба зоны стережёт
  это с нашей стороны: в ответе нет ни одного своего заголовка;
- **не полагается на `Content-Type`.** Мы отдаём `application/octet-stream` (внутрь не смотрим и
  разбора не обещаем), чужая раздача назовёт тип как ей угодно.

### Коды отказов

Код — машине, причина и выходы — человеку (`2.3`). Проба стережёт **код**, а не формулировку.

| HTTP | code | когда |
|---|---|---|
| 401 | `no-creds` | пароль не назван |
| 401 | `bad-creds` | пароль не подошёл |
| 404 | `no-state` | раздача поднята, состояние ещё не записывали |
| 404 | `no-such-address` | спросили не корень |
| 405 | `bad-handle` | метод не из двух (в ответе `Allow: GET, PUT`) |
| 400 | `empty-state` | пришло ноль байт — это стёртая личность, а не пустая |
| 400 | `state-not-received` | тело оборвалось на полпути; старое состояние не тронуто |
| 413 | `state-too-big` | больше предела записи |
| 500 | `state-unreadable` · `state-unwritable` | том, права, место |

**`no-state` — не поломка, а развилка:** так отвечает свежая раздача, в которую состояние ещё не
клали. Заводящий скоуп на это и опирается.

### Цена, названная вслух

- **последний пишущий затирает предыдущего целиком** (`3.4`). Пока пульт один, этого не
  случится; двое пишут разом — запись одного пропадёт молча. Ни слияния, ни условной записи
  здесь нет намеренно: это глубь ветки, и открывать её заново незачем;
- **пароль едет по HTTP открытым.** Базовый слой секьюрности в мире один — пароль (`3.4`); всё,
  что сверх (туннель, TLS, свой сторож), строит сам юзер: это его вилка, мир не запрещает и не
  требует.

## 2. Наша вилка — что мы выпускаем

**Одна вилка как удобство, а не как единственно возможная.** Всё в этом разделе заменяемо на
что угодно, что держит раздел 1.

| | |
|---|---|
| образ | `ghcr.io/omnifield/world-share` — один статический бинарь, **больше в образе нет ничего** |
| рецепт | `share/compose.yaml` — им раздачу поднимают на названной машине |
| порт | `8070` (дверь — 8080, контроллер — 8090; одна машина законно держит все три) |
| состояние | `/state/scope.json` в томе `<имя>-state` |
| пароль | `SHARE_PASSWORD` при подъёме; **без него раздача не поднимается вовсе** |

Ни шелла, ни пакетного менеджера, ни `curl` в образе нет: раздача держит личность юзера, и всё,
что лежит рядом с ней, лежит рядом с его ключами. Стук в живость — команда самого бинаря
(`share knock`), а не отдельный инструмент.

### Значения

| | |
|---|---|
| `SHARE_PASSWORD` | обязательно, без умолчания |
| `SHARE_ADDR` | `:8070` |
| `SHARE_STATE` | `/state/scope.json` (в репозитории — `./.state/scope.json`) |
| `SHARE_LIMIT` | предел одной записи, байт; по умолчанию `1048576` |
| `SHARE_KNOCK_TIMEOUT` | сколько секунд ждёт стук |

Предел — не мнение о содержимом, а граница памяти и диска: без него одна оборванная запись
затягивается на весь том.

### Подъём на машине юзера — тем же путём, что и любая вещь

Раздача поднимается **рецептом**, а не кодом контроллера (`WORLD2-131`):

```
SHARE_PASSWORD=<пароль> ./deploy/remote.sh add <имя> --addr user@машина --recipe share/compose.yaml
```

Пароль подставляется компоузом при подъёме. Не назван — **компоуз краснеет здесь**, до того как
что-либо уехало на чужую машину (`:?` в рецепте), а не «контейнером, который упал там».

Появление раздачи не потребовало ни строки в соседних зонах — только этот рецепт и образ.

### Путь разработчика зоны

```
SHARE_PASSWORD=… ./share/up.sh          поднять здесь (порт 8070)
SHARE_PASSWORD=… ./share/up.sh --build  собрать образ из исходников и поднять
./share/up.sh status                    контейнер, здоровье, том личности
./share/up.sh down [--with-state]       снять; с ключом — вместе с личностью
go run ./cmd/share help                 то же без докера
```

## 3. Чем это проверено

```
./share/probe-share.sh          зелёный и красный прогон (умолчание)
cd share && go test ./...       пробы кода
```

Проба стережёт **свойства**, а не «работает ли»: две ручки и файл целиком · внутрь файла не
смотрим (проходит заведомо не-JSON) · пустые разделы и пустой бренд законны (`WORLD2-135`) ·
пароль проверяет сама раздача · отказ приходит тройкой · **ни одного своего знака в протоколе** ·
запись затирает предыдущую целиком.

Ломаем нарочно: без пароля не поднимается · без кред · неверный пароль (и запись под ним **не
доезжает до диска**) · третья ручка · раздел в пути · ноль байт · сверх предела.

**Без докера проба не зеленеет, а говорит вслух:** образ и рецепт остаются непрогнанными, и код
выхода `3` — НЕПОЛНЫЙ ПРОГОН. «Проверили, что смогли» и «проверили» — разные слова.

---

## 4. Чего в зоне нет — и это не забывчивость

| чего нет | почему |
|---|---|
| ручек по разделам (ключи отдельно, территории отдельно) | файл целиком, и точка (`3.4`) |
| разбора и проверки содержимого | это дело контроллера; наша проверка завела бы вторую правду о формате |
| условной записи, слияния, версий состояния | цена названа вслух, глубь ветки (`3.4`) |
| TLS, вторых факторов, доверия контроллеру | слой юзера, не мира (`3.4`, «Секьюрность — слоями») |
| списка контроллеров, журнала правок, тождества копий | их не существует в модели (`3.4`) |
| членства в сети мира | раздача не служба мира: личность старше любой двери |

Работа: `WORLD2-132`, ветка `feat/scope-by-address`.

**Сверка с рынком 2026-08-17** (перед тем как заводить форму): смотрели HTTP `GET`/`PUT` над
одним адресом (RFC 9110, §9.3.4 — `PUT` заменяет состояние ресурса телом, идемпотентен),
`Basic` (RFC 7617) и WebDAV (RFC 4918). **Берём первые два, WebDAV не берём:** он про каталоги,
свойства и блокировки (`PROPFIND`, `LOCK`, `MKCOL`), и чужой вилке пришлось бы повторять весь
набор, чтобы считаться раздачей, — ровно та цена, которую канон запрещает перекладывать на
изготовителя вилки. Своего протокола не изобретаем ни в одной точке.

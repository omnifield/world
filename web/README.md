# `web` — пульт мира

Клиентская сторона `world`: **пульт** — та же сборка мира, повёрнутая к человеку
(`kb:WORLD-53`). Первая версия показывает одно: **кто сейчас в поле** — список локаций
из-за двери.

Правило, которое действует здесь с первой строки и не обсуждается по ходу:

> Всё, что можно из консоли, можно из пульта; **веб привилегий не получает и своей логики
> не заводит.**

Консоли мира ещё нет — значит эта версия **только читает**. Кнопок «создать локацию» здесь
нет не потому, что не успели, а потому что пульт не может уметь больше консоли. Появятся они
вместе с ней, и проба `«пульт не умеет больше консоли»` покраснеет, если появятся раньше.

Своей модели поля пульт не держит: ни кэша, ни досчитанных полей, ни «локация наверняка ещё
жива». Маршрут локации он тоже не считает из имени, хотя правило известно, — берёт тот,
что назвала дверь. Иначе о том, где локация достижима, в мире появилось бы две истины.

## Поднять

```sh
pnpm -C web install
pnpm -C web dev            # дев-сервер vite, ручки проксируются на дверь
pnpm -C web build          # tsc + статика в web/dist
pnpm -C web test           # пробы (vitest)
```

Адрес двери для **дева** — переменная `WORLD_DOOR`, по умолчанию `http://127.0.0.1:8080`:

```sh
WORLD_DOOR=http://127.0.0.1:8099 pnpm -C web dev
```

Прокси нужен ровно в деве, где vite слушает свой порт, а дверь свой. **В собранном виде
прокси не участвует вовсе:** пульт раздаётся самой дверью и ходит на тот же origin — наружу
машины торчит один порт (`kb:FUND-5`).

Дев-сервер по умолчанию слушает **петлю**, и соседу по docker-сети он не виден. Нужен извне —
поднимай с `--host` и разрешай имя хоста (`server.allowedHosts`), а снаружи машины всё равно
открыт только `:8080`: маршрут туда — забота двери, а не дев-сервера.

## Откуда берутся пакеты — и что сломается без `web/.npmrc`

Фронт стоит на `probe-web` (`kb:PROBEWEB-7`): четыре пакета `@omnifield/probe-web-*` лежат
**только на складе локации `probe-web`**, публично их нет.

```
http://probe-web:4873
```

Склад отвечает соседям по docker-сети `omnifield-gateway` — по имени локации и порту. Вне
этой сети установка не пройдёт, и это ожидаемо, а не поломка.

**В локации `@omnifield` смотрит в GitHub Packages**, а там лежит только старая редакция
`@omnifield/probe-web@0.1.0`. Поэтому скоуп переопределён файлом зоны — [`.npmrc`](.npmrc):

```
@omnifield:registry=http://probe-web:4873
//probe-web:4873/:_authToken=baser-registry
```

Токен любой непустой: прав доступа у склада нет, но без токена менеджер отказывается сам,
ещё до похода на сервер.

**Что сломается без этого файла — и почему это опаснее обычной поломки.** Установка пройдёт
**зелёной** и приедет старая редакция: отказа не будет, экран будет, а поверхность окажется
не та. Отсюда правило проверки: «пакет не находится» или «ведёт себя странно» — первым делом

```sh
npm config get @omnifield:registry     # ожидаем http://probe-web:4873 внутри web/
```

а не склад. Скоуп-настройка сильнее флага `--registry` и бьёт молча.

**Почему файлом зоны, а не `npm config set --location=user`**, как написано в миниdoc'е
потребителя: пользовательская настройка сильнее и бьёт по **всей локации**, включая чужие
пакеты `@omnifield`. Наша зона — `web/`, здесь и настраиваем; проектный `.npmrc` перебивает
пользовательский ровно на этой папке.

`pnpm-workspace.yaml` рядом — не раскладка монорепы, а карантинный список менеджера
(`minimumReleaseAgeExclude`): pnpm придерживает свежеопубликованные пакеты, а наши четыре
именно свежие. Файл дописан установкой, а не рукой.

## За что держимся у probe-web — четыре точки

Замороженная поверхность (`kb:PROBEWEB-7`), всё остальное в их пакетах внутреннее:

| точка | где у нас |
|---|---|
| `mount()` из `-runtime` | `src/main.tsx` |
| `defineConfig` из `-build/vite` | `vite.config.ts` |
| `-build/tsconfig` | `tsconfig.json` |
| `defineTestConfig` из `-build/vitest` | `vitest.config.ts` |
| точка `#root` | `index.html` |

Скелет положен **руками** по описанию из `kb:PROBEWEB-7`: консоли `baser` в нашей локации
нет, и `baser add` не закладывается.

Оформление живёт в `src/panel.css`, а не блоком `<style>` в `index.html`: файл положен один
раз, и вписанное в него замёрзло бы навсегда. Кит безголовый — примитивы одеваем по зацепке
`data-slot` и токенам темы, литеральных цветов не держим (иначе они не переключаются вместе
с темой и всплывают пятном в тёмном режиме).

### Одна добавка поверх пресета проб

`vitest.config.ts` дописывает к `defineTestConfig()` одну строку: `server.deps.inline` по
расширению `.jsx`. Причина — примитивы кита стоят на `@kobalte/core`, а тот и его соседи по
экосистеме Solid отдают по условию `solid` непреобразованный JSX файлами `.jsx`; раннер грузит
зависимости в обход трансформации и спотыкается о расширение. Чинится у нас сегодня, но
**принадлежит зоне `build`**: любой потребитель, взявший `-ui` и написавший пробу на
компонент, упрётся в то же самое. Заявка наверх — комментом в `tasker:WORLD-32`.

## Откуда берутся данные — контракт двери

Единственное место разговора с миром — `src/door.ts`. Ручка реестра (зона `core`,
`tasker:WORLD-31`):

```
GET /api/locations
  200 → {"count": N, "locations": [{name, addr, gives, since, route}]}
  отказ → {"error": "<код>", "detail": "<причина и выход>"} с кодом состояния
```

Пульт показывает ровно эти поля: имя (оно же ссылка по `route`), что даёт, адрес в сети и
когда локация в поле. `since` необязательно — без даты список показать можно, соврать датой
нельзя.

## Три состояния экрана

| состояние | что видно | чем держится |
|---|---|---|
| **список есть** | строка на локацию: имя-ссылка, что даёт, адрес, маршрут, с какого времени | — |
| **список пуст** | «В поле сейчас никого» и объяснение словами | `kb:WORLD-2`: незанятая роль — не недоделка. Пустое поле **не отказ** и не красится отказом |
| **дверь недоступна** | код отказа, причина и **что делать**, плюс кто отказ произнёс | `kb:WORLD-31`: отказ обязан называть причину и выход |

Отказ, названный **самой дверью**, проходит насквозь и своими словами не переписывается: по
канону её `detail` уже содержит выход, и приписывать свой значило бы сказать человеку два
разных «что делать». Поэтому у такого отказа поле `exit` пусто, а на экране стоит
«произнесено: дверью». Всё, что пульт сочиняет сам, **обязано** нести выход — это стережёт
отдельная проба, а не договорённость.

Экран отказа не красная полоса: кайма и код. Красным красят поломку, а отказ мира —
работающее правило.

## Проверка перед коммитом — каденс на человеке

Машинного pre-commit в репозитории нет. Перед каждым коммитом:

```sh
pnpm -C web typecheck     # tsc -p .
pnpm -C web test          # vitest run
pnpm -C web build         # tsc + vite build
```

**И отдельно — порча нарочно.** `kb:WORLD-32`: проба, которую ни разу не заставили упасть,
пробой не является. Меняешь охраняемое поведение — сломай его руками и убедись, что проба
покраснела. Прогон 2026-08-10: десять порч (пустое поле объявлено отказом · у отказа отобран
выход · маршрут досчитан из имени · битая строка реестра пропущена молча · чужое тело вылито
целиком · пустое поле показано пустым экраном · пустой блок «что делать» · кнопка управления
полем · ссылка по имени вместо маршрута · отказ не называет, кто его произнёс) — покраснели
все десять.

## Чего в зоне нет намеренно

- **своей модели поля** — ни кэша, ни вычисленных полей, ни состояния между запросами;
- **управления полем** — пока нет консоли мира, см. первый раздел;
- **правил мира** — почва, гравитация, атмосфера сюда не разложены (`tasker:PILOT-13`), и
  пульт их появление не приближает и не подменяет.
